## 1. 项目概述

Cluster Intelligence 是一套**基于网络流量特征的拓扑可视化与安全域分析平台**：前端用 D3.js 力导向图直观展示机器（IP）之间的访问关系，后端结合 **Neo4j 图数据库 + GDS 图算法**与 **Python 数据建模/富化脚本**，支持安全域划分、安全基线配置、异常检测与多格式数据导入。

当前项目的核心命题是：**在缺乏社区结构（星型采集拓扑）的数据上，让"安全域划分"仍然可信、可解释**。为此实现了"三层安全域"（L1 物理域 → L2 业务 Louvain → L3 属性细分）划分算法与可信度评估指标。

### 关键特性一览

| 特性 | 说明 |
| --- | --- |
| 拓扑可视化 | D3.js 力导向图，缩放/拖拽/搜索/高亮邻居/聚焦安全域 |
| 安全域划分 | 8 种聚类策略 + 三层安全域（标准/更细/极细三档粒度） |
| 图算法 | Neo4j GDS：Louvain / WCC / PageRank；无 Neo4j 时本地降级计算 |
| 异常检测 | 前端 Isolation Forest 训练 + Python 侧异常评分富化，分级（Critical/High/Medium/Low）展示 |
| 数据富化 | Python Enricher 管道（geo / 服务识别 / 端口服务 / 子网判定 / 异常评分） |
| 数据导入 | Excel 原始流量日志、拓扑 JSON、Neo4j 一键加载 |
| CMDB 预留 | CMDB 标签提取 + 属性加权相似度 + Top-K 相似节点（待接入真实数据） |

## 2. 核心功能

### 2.1 拓扑图可视化
- D3 力导向渲染，节点按安全域着色，边粗细映射通信权重
- 支持缩放、拖拽、节点搜索定位、点击选中、邻居高亮
- 三种布局预设：力导向（force）/ 径向（radial）/ 安全域（community）
- 力模拟参数（边距/斥力/中心力/碰撞半径）可在设置中实时调节
- 异常节点显示**红色脉冲光圈动画**，视觉优先级最高
- 按边权重分位数过滤、按节点度数过滤、标签显隐切换
- N 跳邻居展开（点击节点扩展子图，支持本地与 Neo4j 两种来源）
- 最短路径（攻击链）查询与路径高亮

### 2.2 安全域划分（重点）
支持 8 种聚类策略：

| 策略 | 依据 |
| --- | --- |
| `/24 子网` | 按 IP 前三段分组 |
| `端口数量` | 按端口数分档（0 / 1-2 / 3-5 / 6-10 / 10+） |
| `协议类型` | TCP / UDP / 混合 |
| `端口类型` | Web / 数据库 / 缓存 / MQ / 邮件等 |
| `IP 十位段` | 按第三段十位分档 |
| `服务类型` | 按推断的服务角色 |
| `按 zone_label` | 按标签字符串细分 |
| `三层安全域` | L1 物理域 + L2 业务 Louvain + L3 属性细分 |

**三层安全域（security_v3）**算法流程：
1. **L1 物理域**：识别核心基础设施节点（高连接数或基础设施端口），其余按 `zone_id` 或 `/24` 子网划分物理基域
2. **L2 业务社区**：在每个基域内用**业务边**（排除基础设施端口边）跑 Louvain，模块度超过阈值才拆分
3. **L3 属性细分**：按属性签名（子网/29、方向、端口组合、服务、角色、出入度、异常级别等）继续细分，支持"标准 / 更细 / 极细"三档粒度与 Enrich 标签叠加

配套"**三层安全域可信度**"卡片：模块度、域内连接占比、平均域规模、单节点域数量、与 zone_id 重合度。

### 2.3 安全策略
- **安全基线**：可配置规则（异常分数、流量字节、度数、端口熵），字段 + 操作符（gt/lt/eq/between）+ 阈值 + 严重级别，自动检测违规节点
- **白名单**：将节点标记为白名单，抑制其异常告警（置空异常分数/级别）

### 2.4 异常检测
- 前端 `dataConverter` 中用 **Isolation Forest**（100 棵树）对度、入/出度比、端口多样性、社区大小等 5 维特征训练并评分
- Python 侧 `anomaly_score` enricher 用度中心性 + is_hub + 端口数计算异常分并归一化到 [0,1]
- 等级阈值：Critical > 0.75，High > 0.60，Medium > 0.45，其余 Low

### 2.5 数据导入
- **Excel（.xlsx/.xls）**：原始流量日志（proto/src/dst/dport/deviceDirection…），经 `/api/import` 转换
- **JSON**：标准拓扑数据（nodes/links/metadata）
- **Neo4j**：一键从图数据库拉取完整拓扑
- **业务建模数据**：加载 `public/topology_data_business.json`
- 支持拖拽上传

### 2.6 数据富化（Enricher）
前端节点详情面板可对单个 IP 触发 Enricher（调用 `/api/enrich` → Python `enrich_single_ip.py`），结果即时回填到节点属性。

## 6. 核心算法与机制

### 6.1 三层安全域（src/lib/clustering.ts `security_v3`）
- **L1**：核心基础设施节点（邻居数 ≥ max(50, 30%节点数)，或 ≥2 个基础设施端口且邻居 ≥ max(20, 10%)）→ `core_infra`；其余按 zone / /24 子网分物理域
- **L2**：每个基域内对**业务边**跑 Louvain，模块度 ≥ 阈值（标准 0.3 / 更细 0.15 / 极细 0）才拆分子域
- **L3**：属性签名细分（/29 子网 + 方向 server/client/peer + 端口组合 + 服务/角色 + 度数档 + 异常级别…），粒度越细加入特征越多
- 输出模块度 / 域内边占比 / 平均规模 / 单节点域数等**可信度指标**

### 6.2 图算法（Neo4j GDS + 本地降级）
- **Louvain**：`gds.louvain.stream`，`maxLevels` 控制粒度（小 = 细）；社区数 < 2 或模块度 < 0.2 时**自动降级**为规则聚类（/24 网段 + IP 尾号 10 一档分块 → physical_zone）
- **WCC**：连通分量划分
- **PageRank**：关系权重加权，Top10 枢纽节点
- 结果可持久化为 `gds_*` 属性 + `GDSZone` 节点 + `IN_GDS_ZONE` 关系
- **本地降级**：Neo4j 不可用时，`localGds.ts` 用纯 TS 实现 WCC / Louvain / 属性细分（`gds_louvain*1000 + 属性子域索引`），保证功能可用

### 6.3 异常检测
- **Isolation Forest**（TS 实现）：5 维特征（度、入/出度比、端口数、社区大小、度/社区比），`s(x,n)=2^(-E(h(x))/c(n))` 评分
- **anomaly_score enricher**（Python）：度中心性 + is_hub + 端口数 → 评分，管道末尾归一化 [0,1]
- 分级阈值：0.75 / 0.60 / 0.45 → Critical / High / Medium / Low

### 6.4 Enricher 管道（Python，flowsint 风格）
注册表机制：`@enricher` 装饰器注册 → `config/enrichers.yaml` 控制启停与参数 → `Pipeline` 按实体类型分桶执行 → `new_entities` 进下一轮（BFS 扩展）。

内置 5 个 Enricher：

| name | category | 处理类型 | 功能 |
| --- | --- | --- | --- |
| `ip_geo` | Geo | IP | RFC1918 内网识别 + 公网 ip-api.com 查询（默认关闭） |
| `service_type` | Service | IP | 端口集合 → 服务大类（Web/DB/Cache/MQ…） |
| `port_service` | Service | IP | 端口 → 具体协议（80/HTTP），生成 `:Service` 节点 + `:RUNS` 关系 |
| `subnet_cidr` | Network | Subnet | CIDR → 私有/loopback/multicast 判定 |
| `anomaly_score` | Risk | IP | 度中心性 + is_hub + 端口数 → 异常评分 |

每步产出 `EnrichmentResult {properties, relationships, new_entities, errors}`。

### 6.5 CMDB 相似度（预留）
`cmdbSimilarity.ts`：6 个字段加权 Jaccard（业务组 0.4 / 应用 0.25 / OS 0.15 / 环境 0.1 / 负责人 0.05 / 标签 0.05），支持 Top-K 相似节点与相似图构建（阈值 0.5）。

### 6.6 数据转换（原始日志 → 拓扑）
`dataConverter.ts`：IP→节点、通信→边聚合；graphology 跑 Louvain（自适应 resolution：稀疏 1.5 / 密集 0.8）；社区数 ≤ 2 或最大社区 > 50% 时**回退规则分组**（子网 + 端口范围 + 角色 + 方向）；小社区合并；Isolation Forest 算异常分；生成域名（类别-角色-方向-子网）。

| GET | `/api/nodes` | 节点邻居查询 | 占位（待接 Neo4j） |

> Neo4j 通信通过 `src/lib/neo4j.ts` 的**纯 fetch HTTP 事务端点**（`/db/neo4j/tx/commit`），零依赖；path/neighbors 路由使用 `neo4j-driver`（Bolt）。

## 12. 设计规范

- **意象**：深夜安全运营中心（SOC）——深色背景上发光的数据点，节点如星辰漂浮，异常节点红色脉冲闪烁
