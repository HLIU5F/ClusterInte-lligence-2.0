# Cluster Intelligence 项目交接文档

## 1. 项目一句话概况

基于流量特征的网络拓扑可视化与安全域分析平台：Next.js 前端 + D3 力导向图 + Neo4j/GDS 图数据库 + Python 数据建模，当前重点是让“安全域划分”在缺少社区结构的数据上仍然可信、可解释。

## 4. 数据现状与口径

### 原始数据

- 完整数据：3738 节点 / 6499 边，星型结构。
- 两个采集大节点：
  - `10.26.0.26`：连接 3736 个节点
  - `10.20.3.25`：连接 2553 个节点
- 第三个核心节点：`10.100.113.134`，连接 213 个节点。

### 业务核心图（推荐用于安全域分析）

- `scripts/topology_data_core.json`：212 节点 / 211 边。
- 生成方式：去掉两个采集节点 + 剔除失去全部连接的孤立节点 + 回填端口。
- 三层安全域结果（标准/更细/极细均为 59 域）：
  - 模块度 `-0.2559`
  - 平均规模 `3.59`
  - 单节点域 `14`
  - 域内连接 `0%`

### 全量非采集图（资产清单用）

- `scripts/topology_data_no_hubs.json`：3736 节点 / 211 边。
- 保留全部非采集节点并回填端口。
- 三层安全域：标准 1553 / 更细 1553 / 极细 1704。

### 当前 Neo4j 数据

- 212 节点 / 211 边，与 `topology_data_core.json` 对应。
- `GET /api/topology/neo4j` 已验证返回 200。

### 为什么 59 是当前可信上限

每个域内节点在可用属性上完全一致：同一 zone、同一 /29、同一方向、同一端口组合、同一角色/异常级别，且域内基本没有业务边，图算法无法继续切分。再拆就是单节点域，不再有安全语义。

## 5. 已完成的重要改造

### 数据与脚本

- `scripts/build_business_graph.py`：业务图建模，识别采集节点、端口分类、生成 `topology_data_business.json`。
- `scripts/remove_large_nodes.py`：
  - `--mode core`：输出 212 节点业务核心图。
  - `--mode all`：输出 3736 节点全量清单。
  - 会回填节点 `ports`，并输出分析报告。

  - 支持 CMDB 字段：`business_group / os / application / owner / environment / cmdb_tags`。

## 8. 环境坑与注意事项

- Neo4j 容器偶尔会 `Exited 137`，API 会 500；先 `docker ps`，再 `docker start neo4j-db`。
- 3100/3200 开发服务器容易被进程清理；用 `Start-Process -WindowStyle Hidden` 或 `pnpm.cmd dev -p 3100` 重启。
- 沙箱默认只读时，写 `D:\桌面\projec\Cluster-Intelligence` 需要授权；同步文件用 Copy-Item。
- `python -m py_compile` 可能因 `__pycache__` 权限失败，不代表语法错误。
- `pnpm install` 可能因 `ERR_PNPM_IGNORED_BUILDS` 返回非 0，node_modules 仍可用。
- 不要用 `rg` 不行时就用 `Select-String`/`findstr`；中文路径 PowerShell 输出可能乱码，但文件内容正常。
- 项目已去掉 Google Fonts，构建不再依赖外网字体。
